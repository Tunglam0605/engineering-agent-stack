# Gap analysis and insertion points

## Architecture alternatives

**ADOPT declarative composition before stack-controlled decisions.** A single resolved snapshot is supplied to preflight, lifecycle checks, context construction and adapter rendering. This fits the existing separation of role, semantic compute profile, provider, policy and provenance. It adds a contract and composition responsibility, not another orchestrator.

**EXPERIMENT with loose skills plus a project profile** only as a smaller alternative. It avoids package management but leaves compatibility, content identity and repeatability fragmented. Useful for evaluating a minimal skill workflow, insufficient as the final manifest/preset contract.

**REJECT executable plugins, recursive preset inheritance and domain agent catalogs** for v0.6. They enlarge the enforcement surface and routing vocabulary without local benchmark evidence. Existing roles plus skills/rules express embedded, ROS2 and release specialization. This agrees with the prior [local synthesis](../architecture-synthesis.md).

## Observed execution boundary

The [architecture](../../../docs/ARCHITECTURE.md) explicitly limits stronger guarantees to stack-controlled operations. Actual paths are:

```text
already classified signals -> evaluate_routing.resolve (fixture evaluator)
explicit request -> resolve_delegation.result_payload -> DelegationPreflight.evaluate
                 -> PASS-only ResolvedExecutionPlan

goal CLI -> LifecycleGate.evaluate or evaluate_and_commit -> durable assignment
workflow CLI -> Workflow -> GoalStore lock/revision/snapshot

canonical YAML + model config + Codex map -> generator -> seven TOML roles
CLI install/init -> installer -> personal/project Codex artifacts
```

There is no integrated dispatch transaction joining these paths. The resolver does not call lifecycle and the lifecycle gate does not validate a delegation request, provider capability, model resolution or independent-review plan. `REUSE`, a committed pending assignment and a recovery receipt are not native-dispatch receipts. Extension activation must not make any of them appear to be one.

## Material gaps to resolve before implementation claims

1. **Unified admission evidence:** current preflight and lifecycle independently approve different facts. A future stack controller must require both, retain matching task/role/scope/resolution IDs and revalidate mutable state before dispatch. There is still no transaction covering external provider execution.
2. **Policy vocabulary:** reconcile classified `risk`, evaluator `review_class` and runtime `risk_class`; unknown or conflicting high-risk evidence must escalate rather than default to normal. This is a design requirement inferred from the differing interfaces, not a demonstrated exploit.
3. **Rule enforcement:** no generic domain validator registry or acceptance/release transition gate exists. A rule marked `gate` is ineligible for activation until a trusted implementation and controlling boundary are available. Checkpoint stage text cannot substitute for that boundary.
4. **Schema strictness:** current schema documents and handwritten checks are useful baselines, but do not provide general duplicate-key, closed-object, resource-limit and semantic compatibility enforcement for untrusted packages.
5. **Recovery reproducibility:** current snapshots do not preserve the policy version loaded for earlier work. Adding config fields to version 2 without changing readers risks ignored/lost metadata; use an explicit state-version transition.
6. **Artifact ownership:** canonical seven-role byte comparison is not enough to uninstall or update outputs generated from a selected preset and several packages. Retain baseline roles and introduce separate ownership only if materialization is needed.
7. **Scope granularity:** per-goal lifecycle locking is not global cross-goal write leasing; preflight receives leases from the caller. A new layer must not claim cross-goal/project-wide exclusion or granular native permission enforcement without a controlling implementation.
