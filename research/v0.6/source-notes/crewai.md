# crewAIInc/crewAI

Pinned upstream: `7e18abd1088ea0b10f4a449d27d3335bd7f16650` (GitHub main at research time). Repository and license: https://github.com/crewAIInc/crewAI (MIT). I inspected implementation, tests, and configuration at that tree; observations below are paraphrased.

**Problem solved.** crewAI composes role-described agents into sequential/hierarchical crews and event-driven Flows, with tool calls, memory, and optional persistence. The `src/crewai/project/crew_base.py` decorators discover `agents_config` and `tasks_config`; `src/crewai/crew.py` loads agent/task dictionaries and expands `{variable}` inputs when constructing `Agent` and `Task`. YAML examples live under `src/crewai/cli/templates/` and are exercised by `tests/` project/config fixtures.

**Composition and execution.** `src/crewai/crew.py` owns kickoff, process selection, manager creation, delegation, task ordering, callbacks, and output aggregation. `src/crewai/flow/flow.py` defines `@start`, `@listen`, and router-style transitions; `src/crewai/flow/flow_state.py` carries typed flow state. Tool registration and invocation are in `src/crewai/tools/base_tool.py`, `tool_usage.py`, and `agent.py`; the agent validates tool schemas and executes through the configured LLM adapter. Persistence is optional: Flow persistence implementations are in `src/crewai/flow/persistence/` (SQLite backend and serializers), while crew memory/storage integrations are under `src/crewai/memory/` and `src/crewai/memory/storage/`.

**Validation, tests, security.** Pydantic models in `src/crewai/agent.py`, `task.py`, `crew.py`, and `flow/` reject malformed contracts and constrain process values; `tests/` contains config loading, flow routing/state, tool execution, delegation, and persistence fixtures. YAML is application/project input, not a trusted extension mechanism: interpolation and dynamic Python imports used by project discovery mean untrusted project trees/configuration must be isolated. Tools execute arbitrary host-side code by design, and delegation can multiply calls/cost, so approvals, budgets, filesystem/network policy, and audit receipts remain an outer runtime concern.

**Decisions for EAS.** **ADOPT** explicit agent/task/flow contracts, typed state, bounded transitions, deterministic config paths, and validation tests. **ADAPT** decorator ergonomics as declarative manifests with provider-neutral role identity; represent tool permissions, persistence, and delegation in separate execution-policy/provenance fields. **EXPERIMENT** with Flow-like event edges only where schemas and budgets are statically checkable. **REJECT** specialist-agent explosion (one role per task), executable extensions/plugins, implicit model/provider authority, remote config loading, and unrestricted tool/delegation execution.

**Local impact.** Informs `research/v0.6/contract-freeze.md` and the agent/routing/policy schemas. No third-party prompt or source was copied; provenance is this pinned MIT repository and the URL above.
