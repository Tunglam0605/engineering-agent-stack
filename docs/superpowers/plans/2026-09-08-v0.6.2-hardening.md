# v0.6.2 Hardening Implementation Plan

> Execute inline using the executing-plans skill; obtain an independent read-only review before commit. The user authorized work directly on main and the full gated release sequence.

**Goal:** Build once per workflow run, validate exact wheel/sdist bytes on Linux and Windows, and promote those same bytes to GitHub Release.

**Architecture:** A Linux build job creates one wheel and one sdist plus a strict SHA-256 JSON manifest. Its immutable artifact ID and manifest digest are job outputs. Validators and publish download that ID and verify the manifest against the independent digest, candidate version and commit before consuming files. Publish depends on both validators and never builds. Main CI exercises the same flow; tag release has its own single build and validation DAG.

**Tech stack:** Python 3.9 standard library, unittest, GitHub Actions artifacts, gh CLI.

**Spec:** User's v0.6.2 hardening request, repository AGENTS.md, and docs/DISTRIBUTION.md release gates.

## Constraints

- Exactly seven core roles; runtime, declarative capability contracts and all fail-closed lifecycle/recovery/approval boundaries unchanged.
- No v0.7 features, executable extensions, provider overrides, personal managed install changes or unnecessary research edits. Built-in capability versions remain 0.6.0.
- Reproducibility means artifact promotion identity, not deterministic independent rebuilds or dependency locking.
- Missing, extra, renamed, non-regular or hash-mismatched files fail closed. Validate wheel and sdist metadata and all 24 canonical capability resources without extracting archives.
